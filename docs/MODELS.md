# 판단 백엔드 — 실측 (2026-09-19, A100 80 GB 1장)

저작 벤치 20건(30 판정) · 홀 30×30 m 2 MW 100명 · 동일 프롬프트(`typeevac/jev_prompts.py`).
지연은 **서로 다른 상황 20개**를 연속 질의해 측정한다(같은 프롬프트 반복은 `cache_prompt` 때문에 3~5배 낙관적으로 나온다).
한 사람의 결정 = head 4~6개.

## 측정 함정 세 가지 (실제로 밟았다)

1. **프롬프트 캐시** — 같은 프롬프트를 반복하면 llama.cpp 가 프롬프트 처리를 건너뛴다. 초기 보고값 0.28 s/head 는 이 때문이었다.
2. **동시 요청** — GPU 한 장에서는 계산 병목이고, 요청마다 KV 캐시(≈640 MiB)를 밀어내 공용 접두 캐시까지 깬다. 8스레드가 직렬보다 1.8배 느렸다.
3. **생각 모드 기본값** — `JevDecider` 의 think 기본값이 True 였던 탓에 홀 시험이 head 마다 수백 토큰을 생성했다(결정당 42 s). 기본값을 False(즉답)로 고친 뒤 7.2 s/결정, 행동도 개선됐다.

## 다음 개선
