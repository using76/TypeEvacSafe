## 1. 대공간 100선

### 1.1 선정 원칙

1. **용도 분포**: 실제 화재 통계에서 인명 피해가 나는 용도(주거·판매·업무·교육·의료·지하·주차·창고·집회)를 모두 덮는다. 형상이 판단을 결정하므로 같은 용도라도 출구 수·복도 형태가 다른 것을 고른다.
2. **출구 수 1~6**: 유일 출구(아파트·원룸·소형 점포) 30%, 2 출구 40%, 3+ 출구 30%. 사용자 요구 "유일한 출구를 선택" · "여러 출구 중 불 안 난 출구" · "안 몰리는 출구로 변경"이 모두 나오려면 세 부류가 다 있어야 한다.
3. **크기 등급**: 소(≤150 m²) 20 · 중(150~1,000) 40 · 대(1,000~5,000) 25 · 초대(>5,000) 15. 부족한 등급은 기존 형상을 **×0.8 / ×1.25로 축소·확대**해 채운다(문 폭은 고정, 벽 좌표만 스케일 — 사용자 지시 "크기를 늘리고 줄이고").
4. **격자**: dx 0.2(≤400 m²) / 0.25(≤2,000) / 0.4(>2,000). 환경은 시야 패치를 0.4 m 셀로 보므로(`PATCH_DS = round(0.4/dx)`) dx가 달라도 정책 입력 크기는 같다.
5. **화재**: 형상마다 화원 위치 3(**출구 근처** / 중앙 / 출구 반대편)·HRR 2(t² medium 1 MW 도달 / fast 3 MW) = 6 시나리오. 다출구 형상은 "출구 1개 폐쇄" 변형 1개 추가. → 100 × 6 + 70 ≈ **670 케이스**.

### 1.3 시나리오 변형 규칙 (형상당 6~7)

- 화원 위치: `near_exit`(주 출구 3~5 m 이내, 통로 위) / `center` / `far`(주 출구 반대편). `near_exit`가 사용자 요구의 핵심 — 유일 출구 형상에서는 "불을 뛰어넘어 나갈지, 반대로 가서 고립될지"가 여기서 갈린다.
- HRR: t² medium(α=0.0117 kW/s², 1 MW 도달 292 s → T_END 안에서 성장 중) / fast(α=0.0469, 3 MW 도달 253 s). 상한은 유형별(주거 3 MW, 판매 10 MW, 창고 20 MW).
- 다출구 형상: `blocked_1` — 출구 1개를 OBST로 막음(잠긴 문). 관측의 출구 목록에는 남기되 거리장에서 도달 불가 → 정책이 관측과 실제의 불일치를 배운다.
- T_END: ≤400 m² 150 s, 그 이상 240 s. 저장은 1 s 간격 2D 슬라이스(§1.4).

### 1.4 계산·저장 예산과 파일럿

- 실측: `gen_big30` 130×80×15 격자(156k 셀)·50 s가 fds_gpu v2로 **0.9~1.0 분/케이스**. 초대형(A01, dx 0.4 → 395×355×7 ≈ 1M 셀, 240 s)은 셀 7× · 시간 4.8× · dt 2× 완화 → 약 15~20 분. 670 케이스 평균 6~8 분 → **70~90 GPU 시간, GPU 1대로 4일**.
- 저장: 3D 캐시(9 ch × 1M 셀 × 240 프레임 × 4 B ≈ 8.6 GB/케이스)는 불가. **SLCF 2D 평면 슬라이스 3층(z 0.5 / 1.5 / 2.4 m) 9채널**만 출력 → 케이스당 ≤ 100 MB, 670 케이스 ≈ 60 GB → `/home/work/BULC_DATA/evac_big/`(여유 985 GB). 변환기는 3D 캐시 대신 2D .sf를 직접 읽는 `convert_sf2d.py`를 새로 쓴다(FIRE = 3층 HRRPUV 최대, WALL = z 0.5 층(창문 제외), EXIT = 지정 출구 폴리곤, 출구별 거리장 미리 계산).
- **파일럿 5건 먼저**: A01(OBST 66k), A08(127k), A07(다중 메시), B01(재구성), D5 대(150×30). fds_gpu v2가 복셀 CAD와 다중 메시를 받는지, 시간이 위 추정 안인지 확인한 뒤 나머지를 발사한다. 실패 시 Tier A는 OBST 병합(동일 SURF 인접 박스 합치기) 또는 dx 0.4 재격자.

## 2. 환경 v2 — 다중 에이전트·역할·가족·구조

### 2.1 다중 에이전트

- 케이스당 N명(용도별 밀도: 주거 0.05 /m², 판매 0.3, 사무 0.1, 집회 1.0 → 20~200명), 환경 병렬 = 케이스 배치 B × N. 에이전트 간 반발·마찰은 rust_evac 식(A=2000, B=0.08, k=1.2e5, κ=2.4e5)을 `env.py`에 활성화한다(현재 단일이라 비활성).
- 관측 추가: (i) 패치에 **인원 밀도 채널** 1개, (ii) 반경 2.5 m 최대 8명의 상대 위치·속도·역할·상태, (iii) **출구별 요약 벡터**(최대 8 출구): 거리장 값, 방향, 온도, K_s, 화염 2 m 내 여부, 대기 인원 n_e, 폭 w_e, 예상 통과 시간 q_e = n_e / (1.3 인/(m·s) × w_e) [SFPE 유효 유량].
- 종료: 전원 탈출·무력화 또는 시간 한도. 소방관은 자기 FED_heat ≥ 1 시 종료.

### 2.2 역할 (사용자 사양을 다음 정의로 고정 — 수치는 IMO MSC.1/Circ.1533·Purser 계수)

| 역할 | v₀ m/s | 반경 m | FED 계수 | 특이 |
|---|---|---|---|---|
| adult | 1.2 (N(1.2, 0.15)) | 0.20 | 1.0 | 기본 |
| child | 0.8 | 0.15 | tox ×1.3(호흡률) | 단독 판단 없음 — 보호자 `Follow`(rust_evac 리더-팔로워) 반사로 움직임, 보호자 무력화·분리 시 최근접 성인 추종 → 없으면 정지 |
| elderly | 0.7 | 0.25 | heat ×1.2 | 감속 계수 강화(Frantzich 0.081 → 0.12) |
| guardian | adult | 0.20 | 1.0 | 피보호자 1~2명 링크. **환경이 희망속도를 min(자기, 피보호자)로 자동 제한**(동행 반사). 관측에 피보호자 상대 위치·거리·FED |
| firefighter | 1.2 | 0.25 | tox 0(SCBA), heat ×0.2(방화복), 복사 임계 2.5 → 7 kW/m² | 출구에서 t=60~120 s에 진입(역주행). 관측에 반경 15 m 내 위험 피난자 목록(최대 8: 거리·FED·이동 가능 여부) |

**위험 피난자**: FED ≥ 0.3, 또는 5 s 이상 v < 0.2 m/s(연기·군중에 갇힘), 또는 무력화(FED ≥ 1, 이동 불가·운반 필요).
**구조 절차**(환경 규칙): 구조자가 위험 피난자 1 m 이내 도달 → `attach`(확보) → 두 에이전트 속도 min(구조자 v₀, 0.6 부축 / 0.5 운반) → 출구 도달 시 `rescued`. 성인 피난자도 구조자가 될 수 있으나 자기 FED > 0.5면 확보 불가(환경이 막음). 확보 후 구조자 무력화 시 둘 다 무력화.

### 2.3 행동 공간 (계층)

- 저수준(매 0.25 s, PPO): 64-way(희망방향 16 × 속도 배율 4) — 유지.
- 매크로(5 s 주기 또는 사건 시, 판단층 §4): `target_exit`(최대 8 + stay), `mode` ∈ {evacuate, wait_shelter, escort_dependent, rescue_target, follow_crowd, breakthrough}, `rescue_target`. 저수준 정책은 매크로를 관측(one-hot)으로 받고, 거리장은 **매크로가 고른 출구의 거리장**으로 바뀐다(출구별 거리장을 변환 시 미리 계산).
- v1 단계(판단층 전): 매크로는 규칙(가장 가까운 안전 출구, 보호자는 escort, 소방관은 최근접 위험 피난자)으로 채워 저수준부터 학습한다.

| **청정 탈출 보너스** | +50 × max(0, 1 − FED_total) | "연기를 피하고 불을 피해 출구로 나가는 것에 많은 보상" — 나가되 노출이 적을수록 크다 |
| **안전 출구 선택** | 탈출 시 +30 × s_e; s_e = exp(−max(0, T_e−40)/60) · exp(−K_s,e) · 1[출구 2 m 내 화염 없음]. 화재 출구(s_e < 0.3)로 나가면 +100만 | "출구가 여러 개면 불 안 난 출구 선택이 보상 높게" |
| **유일 출구·출구 근처 화재** | 별도 항 없음 — 잠재 셰이핑 γΦ(s′) − Φ(s), Φ = −0.5 × DIST_target. 출구가 불 뒤여도 고립(−50)과 시간(−0.1/s)보다 통과 비용(FED −20·Δ)이 작으면 뚫고, 크면 반대로 가서 고립되는 것이 기댓값상 맞다 | "유일한 출구를 선택 … 불이 너무 강하면 못 가고 반대로 가서 고립" |
| **군중 회피·출구 변경** | 매크로가 목표 출구를 q_e가 더 작은 출구로 바꾸고 실제 그 출구로 탈출하면 +20 (변경 시점의 q 차 ≥ 5 s일 때만); 밀도 > 3 인/m² 구역 체류 −0.05/s | "사람이 몰리면 안 몰리는 출구로 변경 선택에 보상" |
| 압박 | −0.005 × \|f_contact\| | 밀집 위험 |
| 시간 | −0.1/s | |
| FED | −20 × ΔFED, 무력화 −100 종료 | ASET = 페널티 기준 |
| 고립 | −50 종료 | |
| **가족(guardian)** | 피보호자 탈출 +60(자기 탈출과 별개), 피보호자 무력화 −80, 분리(> 3 m) −0.05/s, 피보호자 미탈출 상태로 혼자 탈출하면 자기 탈출 보상 ×0.5 | "아이–엄마아빠 관계" |
| **소방관** | 위험 피난자 확보 +30, 구조 완료 +100, 위험 피난자와 거리 감소 셰이핑 +0.5/m, 자기 FED_heat −20·Δ, 확보 후 무력화 −50, 구조 대상이 없는데 진입해 배회 −0.1/s | "역주행 · 위험 피난자 접근 · 구조 완료" |
| **피난자 구조** | 성인이 확보 +20, 구조 완료 +60 (자기 FED > 0.5면 환경이 확보 자체를 막음) | "구조는 피난자에게도 마찬가지" |

주의: 셰이핑은 모두 잠재 기반(potential-based)이라 최적 정책을 바꾸지 않는다. 출구 변경 보상만 비잠재 항이므로 "변경 자체"가 아니라 "변경 후 실제 탈출"에만 주어 왕복 진동(exit dithering)을 막는다.

## 4. 판단층 — Qwen3.8-Flash-Next 백본 + Jev형 타입 디코더

### 4.1 왜 계층인가

Q4 GGUF 105 GB 백본은 프롬프트 300 토큰 prefill이 A100에서 수십 ms~수백 ms다. 0.25 s 스텝마다 200명을 호출할 수 없다. 대신 **매크로 결정을 5 s 주기(또는 사건 발생 시 — 출구 막힘 감지, 피보호자 분리, 위험 피난자 발견, 목표 출구 s_e 급락)** 로 호출하고, 그 사이의 이동은 PPO 정책이 맡는다. 사용자가 든 "그 상황이 어떠냐, 구조 가능하냐" 같은 판단은 이 매크로 층의 출력이다.

### 4.2 결정 스키마 (Jev의 타입 안전 출력 — 텍스트 생성 없음)

```
Decision {
  target_exit     : Enum[8 + stay]        # 목표 출구
  mode            : Enum{evacuate, wait_shelter, escort_dependent, rescue_target, follow_crowd, breakthrough}
  rescue_target   : Enum[8 nearby] | none
  rescue_feasible : Prob                   # "구조 가능하냐" — Brier 보정
  p_survive_self  : Prob                   # 자기 생존 확률
  urgency         : Ordinal[3]
}
```

### 4.3 입력 — 구조화 상황 서술 (상황 요약기 `situ_text.py` v3)

정적부(케이스당 1회 캐시): 용도, 크기 등급, 출구 목록(위치·폭), 화원 위치.
동적부(호출마다 ≤ 300 토큰): 경과 시간; 자기 역할·위치·FED·속도; 출구별 [거리, 온도, 연기, 화염 여부, 대기 인원, 예상 통과 시간]; 피보호자 [거리, FED, 상태]; 반경 15 m 위험 피난자 [거리, FED, 이동 가능]; 화재 세기 등급.
v2 임베딩 실험(09-17)에서 확인한 규칙을 따른다 — **판단에 쓰이는 정보를 짧게, 앞에, 관계로**.

### 4.4 백본 "개조"의 실제 형태

양자화 GGUF는 역전파가 안 된다. 따라서 개조 = **백본 동결 + 디코더 교체**다.

1. llama-server `--embedding --pooling none`으로 **토큰별 마지막 층 은닉 상태**(L × 2560)를 받는다(현재는 last pooling 1 벡터).
2. PyTorch 측 **타입 디코더**: 학습 가능한 질의 토큰 6개(필드 수) → 2층 cross-attention(백본 은닉에 attend) → 필드별 헤드(Enum softmax / Prob sigmoid / Ordinal cumulative). 파라미터 ≈ 5 M. 이것이 "Jev처럼 만든 디코더"다.
3. 2단계(선택): HF safetensors + QLoRA로 백본 상위 8층에 LoRA. 125B-A6B는 2×A100로 가능하나 학습이 느려, 디코더만으로 부족할 때만 연다.

### 4.5 학습 3단계 (Jev의 supervised → RL → 보정 순서)

(a) **힌드사이트 오라클 지도학습**: 저수준 정책이 학습된 뒤, 각 결정 시점에서 매크로 후보 전부(출구 8 × 모드 6)를 **환경 벡터화로 병렬 롤아웃**해 결과가 가장 좋은 결정을 라벨로, 실제 생존 0/1을 `p_survive` 라벨로, 구조 시도 결과 0/1을 `rescue_feasible` 라벨로 삼는다. 케이스 670 × 결정 시점 30 × 에이전트 표본 → 수십만 라벨. 이 오라클이 없으면 LLM 디코더는 학습 신호가 없다 — **v2의 핵심 데이터 생성기**.
(b) **온라인 RL**(매크로 PPO): 다른 에이전트의 동시 결정이 만드는 상호작용(모두 같은 출구로 바꾸면 그 출구가 막힌다)은 오라클이 못 잡으므로 정책 경사로 보정.
(c) **보정**: Brier + ECE(Jev Phase 4). 확률 필드가 실제 빈도와 맞아야 "73% 생존"이 의미를 갖는다.

### 4.6 E3q 결과에 대한 해석

케이스 임베딩 1벡터를 저수준 정책에 융합한 E3q는 같은 예산의 E3와 차이가 없었다(0.043 vs 0.047). 저수준 이동에는 LLM 정보가 필요 없다는 뜻이지, 판단층에 필요 없다는 뜻은 아니다. v2에서는 LLM을 매크로 결정에만 쓰고 저수준에서는 뺀다.

## 6. 검증

- **동역학**: RiMEA 3.0 테스트 1(기본 속도)·4(밀도–속도 기본도)·6(코너)·8(병목 유량)·12(병목 변화); IMO 1533 테스트 1·4·8·9(출구 선택). 통과 기준은 문서의 허용 범위.
- **행동 단위 시험** (사용자 요구 4종, 각 20 케이스 × 50 시드, 기준선 rust_evac nav 대비):
  1. 유일 출구 3 m 앞 화재: 초기(약한 불)에는 뚫고 나가고, 강해지면 반대로 가서 고립 — 시각별 통과율 곡선이 단조 감소하는가.
  2. 두 출구 중 하나 화재: 안전 출구 선택률 > 90%, 원거리라도.
  3. 두 출구 중 하나 혼잡(N 150): 변경 선택으로 총 RSET이 기준선보다 짧은가.
  4. 가족 3 + 소방관 2: 분리율, 구조 완료율, 소방관 FED.
- **문헌 계수 대조**: Lovreglio et al.(2016) 출구 선택 로짓의 연기·거리·군중 계수 비율과 학습 정책의 선택 확률 비율 비교; Kinateder(2014) 군중 추종 실험.
- **회귀**: home1 30명 시나리오(성인 20·아이 5·노인 5·보호자 10, 현관 1)를 매 단계 고정 시험으로.
